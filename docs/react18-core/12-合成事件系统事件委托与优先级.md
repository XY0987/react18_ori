## React 为什么要做合成事件

如果每个 DOM 节点都直接绑定事件，会有几个问题：

| 问题 | 合成事件的解决方式 |
|------|--------------------|
| 事件绑定分散 | 统一委托到根容器 |
| 浏览器事件差异 | 封装合成事件对象 |
| 事件传播控制 | React 自己维护捕获/冒泡流程 |
| 事件更新优先级 | 执行回调时切换 Scheduler priority |

合成事件系统让 React 可以用统一方式管理事件和事件触发的更新。

## 事件委托：只在根容器监听

简化实现中，`createRoot().render()` 时会初始化 click 事件：

```text
initEvent(container, 'click')
  → container.addEventListener('click', dispatchEvent)
```

也就是说，React 并不是把 `onClick` 直接绑到具体按钮 DOM 上。

真正点击按钮时，浏览器事件先冒泡到根容器，再由 React 的 `dispatchEvent` 接管。

## props 如何和 DOM 节点关联

既然事件不直接绑定在 DOM 节点上，那 React 怎么知道某个 DOM 节点有没有 `onClick`？

答案是：把 props 缓存在 DOM 节点上。

```text
createInstance(type, props)
  → updateFiberProps(dom, props)
  → dom.__props = props
```

后续事件触发时，React 从真实事件的 `target` 开始向上找 DOM 节点，并读取节点上的 props。

## 收集捕获和冒泡路径

事件触发后，React 会从 target 一路向上走到 container：

```text
target
  → parent
  → parent
  → container
```

每经过一个 DOM 节点，就检查它的 props：

```text
onClickCapture → 加入 capture 队列
onClick → 加入 bubble 队列
```

捕获和冒泡的顺序不同：

| 阶段 | 执行顺序 | 收集方式 |
|------|----------|----------|
| 捕获 | 外层到内层 | `unshift` |
| 冒泡 | 内层到外层 | `push` |

所以最终执行顺序是：

```text
capture: outer → inner
bubble: inner → outer
```

## 合成事件对象

React 会基于原生事件创建合成事件对象。

简化实现里，主要增强了 `stopPropagation`：

```text
syntheticEvent.__stopPropagation = false
syntheticEvent.stopPropagation = () => {
  __stopPropagation = true
  原生 stopPropagation()
}
```

这样 React 自己的事件流也能被中断。

如果捕获阶段调用了 `stopPropagation`，冒泡阶段就不会继续执行。

## 事件回调为什么要切换优先级

不同事件的紧急程度不同：

| 事件 | 优先级倾向 |
|------|------------|
| click / keydown / keyup | 高优先级 |
| scroll | 用户阻塞优先级 |
| 普通事件 | 默认优先级 |

执行事件回调时，React 会调用：

```text
unstable_runWithPriority(eventPriority, callback)
```

这样事件回调里触发的 `setState`，在 `requestUpdateLane()` 时就能拿到合适的 lane。

换句话说：

> 事件优先级会影响事件回调中产生的更新优先级。

## 从点击到更新的完整链路

```text
用户点击按钮
  │
  ▼
原生 click 冒泡到 root container
  │
  ▼
dispatchEvent
  │
  ├─ collectPaths：收集 capture/bubble 回调
  ├─ createSyntheticEvent：构造合成事件
  └─ triggerEventFlow
       │
       └─ runWithPriority(clickPriority)
             │
             └─ onClick 回调里 setState
                  │
                  └─ requestUpdateLane → 高优先级 lane
```

## 合成事件和 Fiber 的关系

事件系统本身属于 renderer 层，但它会影响 reconciler 的调度。

关系可以这样理解：

```text
react-dom SyntheticEvent
  → 设置 Scheduler priority
  → setState
  → requestUpdateLane
  → react-reconciler 调度更新
```

这就是 React 模块之间的边界：

- `react-dom` 负责事件和 DOM；
- `react-reconciler` 负责 Fiber 更新和调度；
- Scheduler priority 是两者之间的桥。

## 小结

1. React 事件通常通过根容器委托，而不是直接绑定到每个 DOM 节点。
2. DOM 节点会缓存最新 props，事件触发时从 target 向上读取回调。
3. 捕获阶段用 `unshift` 保证外到内，冒泡阶段用 `push` 保证内到外。
4. 合成事件接管 `stopPropagation`，让 React 自己的事件流可以被中断。
5. 事件回调执行时会切换 Scheduler 优先级，进而影响 setState 的 lane。
