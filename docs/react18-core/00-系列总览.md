## 为什么先做系列总览

读 React 源码最容易踩的坑是：一上来就钻进某个函数，越看越细，但不知道它在整条链路中的位置。

React 18 渲染更新的核心主线可以先简化为：

```text
ReactElement
  → updateQueue
  → scheduleUpdateOnFiber
  → renderRoot
  → beginWork / completeWork
  → commitRoot
  → hostConfig 操作 DOM
```

把首屏挂载再展开一层，可以得到 **6 步心智模型**：

| 步骤 | 做了什么 | 关键函数 |
|:----:|---------|---------|
| 1 | **事件初始化**：在容器上通过事件委托注册监听 | `initEvent(container, 'click')` |
| 2 | **创建更新入队**：将 `<App />` 包装成 Update 对象（含 ReactElement + Lane），加入 HostRoot 的环状链表 updateQueue | `createUpdate` → `enqueueUpdate` |
| 3 | **调度**：根据 Lane 决定走微任务（SyncLane）还是 Scheduler 宏任务，最终调度的是渲染入口函数 `performSyncWorkOnRoot` | `scheduleUpdateOnFiber` → `ensureRootIsSchedule` |
| 4 | **Render 阶段**：以 DFS「递 + 归」方式遍历构建 workInProgress Fiber 树，"递"阶段（`beginWork`）创建子 Fiber 并做 diff，"归"阶段（`completeWork`）创建离屏 DOM 并冒泡 flags | `workLoopSync` → `beginWork` / `completeWork` |
| 5 | **Hook 处理**：当 `beginWork` 遇到 FunctionComponent 时，通过 `renderWithHooks` 切换 dispatcher 执行组件函数，mount/update 各有对应的 Hook 实现 | `renderWithHooks` → `HooksDispatcherOnMount` |
| 6 | **Commit 阶段**：根据 flags 执行真实 DOM 操作（mutation），切换双缓冲树（`root.current = finishedWork`），执行 layout 副作用和 passive effects | `commitMutationEffects` → `commitLayoutEffects` |

> 建议：先记住这 6 步的大框架，再进入后续各篇深入细节，避免"只见树木不见森林"。

所以我会按端到端流程来拆，而不是按文件名机械罗列。

## 核心模块速查

| 模块 | 关键路径 | 主要职责 | 阅读优先级 |
|------|----------|----------|------------|
| `react` | `packages/react` | 暴露 `jsx`、`createContext`、Hooks API，并通过 dispatcher 转发 Hooks 调用 | 中 |
| `react-dom` | `packages/react-dom` | DOM renderer，提供 `createRoot`、事件系统和 DOM 宿主操作 | 高 |
| `react-reconciler` | `packages/react-reconciler` | Fiber、调度、diff、render、commit、Hooks 的核心实现 | 最高 |
| `shared` | `packages/shared` | ReactElement 类型、Symbol、内部共享对象 | 中 |

## 推荐阅读路线

### 第一阶段：打通主流程

1. `packages/react-dom/src/root.ts`
   - 看 `createRoot().render()` 如何进入 reconciler。
2. `packages/react-reconciler/src/fiberReconciler.ts`
   - 看 `createContainer` 和 `updateContainer` 如何创建根节点和首个更新。
3. `packages/react-reconciler/src/workLoop.ts`
   - 看更新如何被调度、render、commit。

这一阶段的目标不是看懂所有细节，而是知道一次渲染从哪里进、从哪里出。

### 第二阶段：理解 Fiber 数据结构

1. `packages/react-reconciler/src/fiber.ts`
   - `FiberNode`、`FiberRootNode`、`alternate`。
2. `packages/react-reconciler/src/workTags.ts`
   - Fiber 节点类型。
3. `packages/react-reconciler/src/fiberFlags.ts`
   - 副作用标记。

这一阶段要重点理解一句话：Fiber 既是组件节点，也是可中断调度中的工作单元。

### 第三阶段：拆 render 阶段

1. `packages/react-reconciler/src/beginWork.ts`
   - “递”阶段：创建或复用子 Fiber。
2. `packages/react-reconciler/src/childFibers.ts`
   - diff 算法：单节点、文本、数组、key。
3. `packages/react-reconciler/src/completeWork.ts`
   - “归”阶段：创建 DOM、冒泡 flags。

### 第四阶段：拆 commit 阶段

1. `packages/react-reconciler/src/workLoop.ts` 的 `commitRoot`
2. `packages/react-reconciler/src/commitWork.ts`
3. `packages/react-dom/src/hostConfig.ts`

这一阶段要关注：render 阶段不改 DOM，commit 阶段才真正落地到宿主环境。

### 第五阶段：Hooks 与并发更新

1. `packages/react-reconciler/src/fiberHooks.ts`
2. `packages/react-reconciler/src/updateQueue.ts`
3. `packages/react-reconciler/src/fiberLanes.ts`
4. `packages/react/src/currentDispatcher.ts`

这一阶段重点理解 Hook 链表、updateQueue 环状链表、Lane 优先级。
